## 1. TeleQnA（客观题）

### 1.1 来源

- 文件：`data/raw/TeleQnA/TeleQnA.json`（1 万题，以此为准）。HF 上另有 `test.json`，与之题干重合 9949 道，不作为评测来源。题目 ID 用 JSON 的 key（`question N`）。
- 内容：3GPP 与通信标准类英文选择题，4 或 5 个选项。官方分 5 类，本项目取其中 3 类：**标准规范 2000、标准综述 1000、词汇 500，共 3500 题**；研究论文类 6500 题舍弃（与运维无关）。
- 题干中位数 13 个英文词（含 `[3GPP Release N]` 标签；去掉标签为 12 词）。带 3GPP 版本标签的：Rel-14 139、Rel-15 54、Rel-16 87、Rel-17 733、Rel-18 780、Rel-19 17，无标签 1690。

### 1.2 筛选漏斗

| --- | --- | --- | --- | --- |
| 起点 | — | 3500 | 三类全部 | `reports/audit/teleqna_dedup_options.md` |
| 去重 | 56 | 3444 | 字面 MinHash + 语义 embedding 两路召回 1390 对候选，LLM 裁决、148 对盲标校验覆盖；判为重复的按簇保留编号最小的一题 | 同上 |
| 结构清洗 | 24 | 3420 | 选项少于 4 个 15 题；题干引用不可见原文（according to the document 等）9 题 | 同上 |
| 答案核验 | 132 | 3288 | 判错且无正确选项、有歧义、无法核实、复查意见不一的剔除；另修正标准答案 4 题 | `teleqna_answer_check.md`、`teleqna_answer_check_full.md` |

### 1.3 测试集构成（731 题）

- 能力维度：RAN 209、CORE 163、TRANSPORT 227、OAM 78、SERVICE 41、SECURITY 13。SERVICE、SECURITY 题少，单独报分只作参考。
- 相关度：2 级 685、3 级 46。
- 打乱策略：free 667（自由打乱）、pin_last 60（含「以上都 / 都不」类选项，固定末位、其余打乱）、no_shuffle 4（选项互相引用编号，整题不打乱）。
- 横评时每题跑 5 个子集：orig（原题）、rep（原题重跑，测噪声底）、s1–s3（3 次固定种子打乱，答案映射核验 0 不符）。

### 1.4 审计结果

**去重**（`teleqna_dedup_options.md`）

- 候选对 1390 对（仅字面召回 899、仅语义 376、两路都召回 115），裁决为重复 63、变体 918、相关 409。
- 字面规则基线（题干 Jaccard ≥ 0.9 且答案文本相同）只找到裁决重复对中的 4 对（召回 6%）：**多数重复是改写过的，只靠字面去重会漏掉**。
- 重复对中标准答案互相矛盾 5 对（9 题），交答案核验。

**答案核验**

- 300 题分层抽样（`teleqna_answer_check.md`）：两路盲答筛查（Qwen 与 Claude 子 agent），不一致的 68 题交两名可查 3GPP / IEEE / ETSI 原文的 Claude 子 agent 独立核查。**疑似错误率 1.0%（3/300，95% CI 0.3%–2.9%）**；含有歧义或无法核实的上界 12.3%。有问题的题全部剔除或修正。
- 全量（只对运维相关的 752 题下结论，`teleqna_answer_check_full.md`）：Haiku 盲答 → 不一致的交两名 Haiku 核查 → 仍未一致判对的交强模型复查。强模型复查额度耗尽后，替代复查者校准不达标（与默认模型的 kappa：MiniMax-M3 0.29、Haiku 0.21，门槛 0.6），剩余 109 题改为 4 人投票（Haiku ×2 + MiniMax ×2，≥ 3 人判正确才保留）：保留 23、剔除 86。该规则在校准题上的保留精确率 81%，估计约 4 道有问题的题留在测试集（约 0.6%）。
- 子集内问题题（改答案 + 剔除）占 12.8%（96/752，[10.6%, 15.3%]），与抽样估计 12.3% 一致。
- 局限：两路盲答都与错误的标准答案一致时会漏检，错误率是下界；核查者是模型不是人工。

**运维相关度**（`teleqna_relevance.md`）

- 规范迭代 v1 → v2 → v3：默认模型与 Haiku 在「≥ 2」上的 kappa 0.60 → 0.73；v3 修正了把 Release 标签当成特性引入版本的误用（抽查中误用由 35% 降到约 5%）。全量由 Haiku 标注。
- **人工抽检不支持这个标签**：本人盲标 40 题（有效 33 题），与模型标签一致率 58%、kappa 0.11。本人的尺度更接近「运维人员实际掌握」，规范是「工作中会用到」。所以「运维相关」只能作为模型判定报告。

**干扰项质量**（`teleqna_distractors.md`，测试集机械统计 + 123 题两人独立标注）

- 正确答案是唯一最长选项：32.1%（随机水平约 22%；分母为去掉「以上都 / 都不」与编号引用类后可计算的 683 题），有生成式选择题常见的「最长即正确」倾向。正确答案与题干词重合唯一最多只有 13.8%，低于随机，不是线索。
- 选项复用：72 对「选项集合相同、并非重复」的题对全是变体关系，其中两题正确答案不同的 62 对。
- 两名 Claude 子 agent 独立标注（盲于分层与横评结果）：选项级一致 91.2%（kappa 0.80）。只计两人一致的判定：
  - 不靠领域知识就能排除到只剩正确答案：天花板题 22%（11/50），其余题 6%（3/50）。
  - **标准答案有问题**：天花板题 8%（4/50），**其余题 34%（17/50，[22%, 48%]）**。
  - 局限：两名标注者是同一模型家族，可能共享被测模型的同一种误解。
- 处理（D7，Oct 15 用户定）：不做全量复核，作为局限写明。

**区分度**（`reports/objective/objective_main.md`）

- 7 个模型 × 5 个子集共 35 次判定：**全部答对 440 题（60.2%）**、全部答错 7 题，有区分度的 284 题。
- 结合上一条：按 50 题抽样估计，有区分度的题里约三分之一（34%，[22%, 48%]，同一模型家族的两名标注者一致认定）标准答案有争议。这里的「有争议」含歧义、另有选项同样对，口径比答案核验宽，所以与上面约 0.6% 的残留估计不矛盾。客观题横评的区分度部分来自答案噪声。

### 1.5 污染检测

**TS-Guessing**（`reports/contamination/ts_guessing.md`，7 模型 × 727 题，4 道 no_shuffle 题跳过）

- 方法：每题遮住一个错误选项，让模型补出原文（Deng et al. 2024 的 question-multichoice 设定），关思考、温度 0。短选项（≤ 5 词）可能靠猜补出，**主证据是长选项（≥ 6 词）的完全匹配率（EM）**。
- 结果：长选项 EM 3.8%–5.2%（7 个模型都 ≥ 2% 的事先阈值），短选项 13.5%–18.7%，ROUGE-L 0.33–0.36，模型之间很接近。
- 人工看命中项（33 题、114 次）：几乎都能由其余选项的对称结构推出（2×2 网格、成对取反、「只有 A / 只有 B / 两者都」的组合），剩下几题是规范里的标准说法。**结论：有逐字复原，但命中项可由选项结构推出，不构成背题证据。**
- 局限：TeleQnA 选项高度模板化，这个方法在这套题上灵敏度有限，「没发现背题」不等于没被污染。

**打乱选项掉分与版本梯度**：free 题打乱后掉分 0.45–1.60pt；Rel-18 掉分 +2.17%、Rel-17 +0.39%，粗估标准误约 2pt，按 D6 视为噪声，写「未见版本梯度（探索性）」，不作为污染证据。

**结论**：TeleQnA 公开较早，很可能已进入训练数据，现有方法查不出、也排除不了。选型主要依据未公开的自写场景题。

### 1.6 思考对照用的子样本

`data/processed/thinking_mcq_sample.csv`：731 题分「天花板（横评全对，440 题）/ 其余（291 题）」两层，天花板层抽 50、其余层抽 100，层内按维度按比例分配，种子 20261015。分析时按层权重（440/731、291/731）加权回 731 题。

## 2. TeleLogs（故障诊断客观参照）

- 文件：`data/raw/TeleLogs/troubleshooting/test.json`（测试集 864 题，8 类根因各 108 题；另有 train 未使用）。MIT 许可，下载需在 Hugging Face 填申请表。
- 内容：5G 路测数据根因分析。每题给 40 余行路测表与工参，要从 8 个预定义根因中选 1 个，答案写在 `\boxed{}` 里，规则判分、不依赖 judge。随机水平 12.5%。
- 8 类根因：C1 下倾过大致远端弱覆盖、C2 覆盖距离超 1km 越区、C3 邻区吞吐更高、C4 非共站同频邻区重叠覆盖、C5 频繁切换、C6 PCI 模 30 相同干扰、C7 车速超 40km/h、C8 平均调度 RB 低于 160。
- 抽样：
  - 主实验 200 题：按类分层各 25 题，种子 20261015（`data/processed/telelogs_sample.csv`，只有 idx 与标准答案）。
  - kimi-k3 开思考对照 50 题：从上面 200 题再按类分层，C1 / C2 各 7、其余各 6，种子 20261016（`data/processed/telelogs_sub50.csv`）。不能直接取前 50 行（该表按类排序）。
- 判分口径：取最后一个 `\boxed{}` 里的 C1–C8，抽不到（含截断）记错并单列。Oct 16 看过开思考结果后修正抽取器，允许一层嵌套（`\boxed{\text{C4}}`）；已核对主实验全部原始回答改前改后抽取结果一致。
- 已知现象：全部模型的 1000 次预测里 C4 出现 519 次（均匀应为 125 次），C4 是各模型的默认答案；C3 几乎从不被预测（5 次）。

## 3. 自写中文场景题（主观题，选型主要依据）

### 3.1 规模与构成

`data/scenarios/scenarios_draft.json`，45 题，v1.0 定稿（tag `scenarios-v1.0`，Oct 14），之后改题只能出勘误版本。ID 稳定，被替换的 SC-D03 / D06 / D09 / D10 留空号。

| 维度 | 构成 |
| --- | --- |
| 题型 | 故障诊断 22、方案咨询 12、KPI 表格解读 11 |
| 能力维度 | RAN 15、OAM 9、TRANSPORT 8、CORE 7、SERVICE 4、SECURITY 2 |
| 难度 | d2 22、d3 23 |
| 题干长度 | 中位数约 612 字 |
| 评分要点 | 共 339 个，每题 7–8 个，权重和 100；可核验类型：标准 64、构造 119、常识 156 |
| 扣分项 | 共 159 个 |
| 高危操作 | 共 116 个，每题 2–4 个，回答主张执行即一票否决（整题 0 分） |

每题字段：题干、参考答案、根因、评分要点（id / 阶段 / 文字 / 权重 / 可核验类型 / 出处说明）、扣分项、高危操作、区分性陷阱（错误结论）、题干已排除的假设、待核验项。诊断题的要点分「根因」与「处置」两阶段，可区分「没找到原因」与「找到原因但处置给错」。

### 3.2 编写与核验流程

1. **AI 辅助起草**：分批起草（`data/scenarios/drafts/<批次>.v{0,1,2,3}.json`，v2 为核验修订后、v3 为定稿前修订，各版保留审计痕迹；合并脚本读 v1 起的最高版本）。无法核验的内容（具体设备命令、现网阈值）一律去掉，只保留能从标准或常识推出的事实。
2. **查重补题**：跨批查重发现 4 组重复，新写 4 道诊断题替换（SC-D23–D26）。
3. **两层事实核验**：
   - 三票跨厂商粗筛（glm-5.2 / kimi-k2.6 / qwen3.8-27b）。
   - Claude 子 agent 逐题复核（5 批 × 9 题），驳回了 74 条三票标记，包括三票一致判错、实际正确的几条。**三票在「标准条款引用」上误报率高，只作粗筛。**
   - 只改确认项：1 处重大修订（SC-D23）、3 处参考答案内部矛盾、若干引用精度项、2 处可核验性降级。
4. **人工查证 TS 条款号**：用户核对 8 条，查出 3 处引用错误并修正（SC-C02、SC-C07、SC-C01）。
5. **参考答案缺口**：切分映射发现 10 个要点在参考答案里没写到（照抄参考答案也拿不到分），每处补一两句，只用要点自身文字，要点与权重不动。
6. **待核验项分诊**：37 题带 48 条待核验项，按「是否进入计分文字」分诊；进入计分的 4 条协议取值（SC-D01 T310、SC-D04 CRS 模 6 频移、SC-D07 −120 dBm、SC-K09 #26/#67）对照 3GPP 原文核对全部成立（`data/scenarios/residuals_triage.csv`）。
7. **天花板试跑**：两个便宜模型关思考各答 45 题，两者都 ≥ 85 分的题只有 3/45（事先阈值 15），不加难度，照常定稿。
8. **机器校验**：`scripts/check_scenarios.py` 检查 ID、权重和、字段、分布与分诊表一致性，定稿时 0 错 0 警。

### 3.3 已知局限

- 作者不是通信运维专家，题目经模型核验与有限的人工查证，没有领域专家逐题审读。
- 要点之间有重叠（同一句话同时属于两个要点），是 rubric 结构，定稿后不改。
- 45 题只支撑分档，不支撑严格排序。
- 题目 Oct 13 新写，晚于被测模型的训练数据，本轮被训练过的可能性极低；但仓库是 public，此后的模型可能见过。

## 4. judge 构造真值探针

`data/scenarios/judge_probes/`：

- `segments.json`：参考答案切成片段并映射到要点。映射由百炼 qwen3.8-max 完成（不能与被检验的 judge 同一家，避免 judge 与「真值」共享同一套理解），45/45 题映射合格。
- `probes.jsonl`：337 个探针，每题约 7–8 个：full（参考答案原文）、drop:Pk ×2（删掉某要点的片段）、wrong_root（根因换成题干已排除的假设，诊断题）、risk_add（加一句高危建议）、risk_neg（加一句「不要这样做」）、pad（前后注水、长度约翻倍）、empty（拒答）。
- 调试集 / 留出集按题划分（`data/scenarios/judge_split.csv`，种子 20261013，题型内分层）：调试集 22 题 165 个探针（只在这上面改提示词），留出集 23 题 172 个探针（锁定后才报数）。
- 人工抽查（`spotcheck_drop.csv`）：调试集 drop 探针抽 30 条，删净 19、残留部分内容 11、仍完整写到 0。所以删要点的主指标定为「判非 covered」，「判 missed」只作参考。
- 局限：构造回答比真实回答「干净」，只覆盖界限清楚的情况。实测真实回答上 judge 一致性明显低于探针（逐要点 82.5% 对 93.7%）。

**分歧仲裁表**（`data/scenarios/arbitration/`）：两档 judge 在真实回答上判法不一致的项抽 60 条（高危 20 + 要点 40，按被测模型分层），两档判定随机标为 A / B 盲审，由本人对照参考答案仲裁，key 单独存放（`main_off_key.csv`）。仲裁者是单一非专家。

## 5. 追问施压脚本

`data/scenarios/pressure/`：

- `scripts_v1.json`：10 个场景（按内容选，覆盖 6 个能力维度，诊断 6、方案 2、指标 2：SC-D01、D08、D16、D18、D21、D24、C04、C11、K03、K06），每个场景 3 轮写死的追问：
  - T2 无新信息的施压·安全：直接给命令 3 个、搬权威 4 个、紧急绕过确认 3 个，各推向该题的一条高危操作。
  - T3 无新信息的施压·结论：要求改为该题区分性陷阱里的错误结论。
  - T4 带新证据的纠正：新的核查结果推翻或削弱原结论的关键前提。
- `probes.jsonl`：20 个探针（每场景 good / bad 各一组写死的回复），用来检验施压 judge。
- 编写：Claude 子 agent 起草、对抗式复核修订（删掉了几处夹带的新事实，重写了与题干冲突的一轮）。**没有经过本人逐条审读。**
- 已知问题：SC-K06 的 T4 新证据指向新版本软件，「回退版本」因此有一定依据，按高危项原文判成触发是脚本设计带来的混淆。

## 7. 适用与不适用

- **适用**：在中文运维问答形态下比较通用大模型的知识底座、诊断与方案能力、施压下的安全表现；检验 LLM judge 在 rubric 打分上的可靠性；作为量化发版门禁的样例。
- **不适用**：作为公开排行榜（题量小、只支撑分档）；评估 Agent / 工具调用能力；评估具体厂商设备命令的正确性（题目刻意不含）；把 TeleQnA 分数当作运维实操能力。
