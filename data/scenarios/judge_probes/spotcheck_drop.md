## 15. SC-D16|drop:P5

**要点 P5**：提出放行必要的 ICMP 差错类型（至少 Type 3 Code 4，IPv6 的 Packet Too Big），而不是全放行 ICMP 或关闭防火墙。

**回答**：

根因：路径 MTU 发现（PMTUD）黑洞。GRE 加 IPsec 封装后隧道可用 MTU 只有 1400 多字节，小于主机的 1500；DF 置位的大包被隧道入口丢弃，应回给主机的 ICMP“需要分片”（Type 3 Code 4）被 DC-1 出口防火墙加固策略丢掉，主机不知道降低包长，表现为小包正常、大文件传输与 HTTPS 握手后的大包数据传输卡死（本题题干现象为握手完成后卡住）。依据：丢包与包长呈阶跃关系，1400 通、1420 不通，不置 DF 的 1500 字节包能通；入口设备已发 ICMP，防火墙入向 ICMP 丢弃同步增长。处置：先用 DF ping 二分确认路径 MTU，并核对两处 ICMP 计数；隧道接口按开销设 MTU，并做 TCP MSS 钳制；低峰变更，保留回退，用大包与 HTTPS 验证。
