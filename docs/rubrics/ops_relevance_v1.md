# 运维相关度与能力维度标注规范 v1

用途：给 TeleQnA 审计后保留的题打两个标签——运维相关度（决定是否进入客观题主体）与能力维度（按维度拆开报分）。

## 一、运维相关度（0–3）

判断标准：**一名移动网络运维 / 优化工程师在日常排障、优化、监控、变更中，会不会用到这道题考的知识。** 只看题目考的知识点，不看题目难度。

| 等级 | 含义 | 典型知识点 |
| --- | --- | --- |
| 3 直接相关 | 日常排障、优化、监控会直接用到 | KPI 与性能测量、计数器；告警与故障处理；SON / MDT / 自优化；切换与移动性参数；覆盖、干扰、容量；负载均衡与资源调度；QoS 保障与拥塞控制；网管、配置与性能管理接口；常见信令流程的失败原因（注册、附着、RRC 建立 / 重建、切换失败） |
| 2 间接相关 | 理解网络行为、读懂信令所需的架构与流程知识 | 网元功能与职责；接口与参考点；主要信令流程的步骤；承载、会话、QoS 流的概念；TCP/IP、以太网、Wi-Fi 的基本机制 |
| 1 弱相关 | 标准编写细节，运维中极少用到 | 具体信元 / 字段编码与取值；物理层公式与参数；某个新特性的设计动机；某 Release 引入了什么；缩写展开 |
| 0 无关 | 与网络运维无关 | RF 人体暴露与生物效应；法规与商业模式；纯学术概念；与通信网络无关的内容 |

边界规则：

- 缩写展开题（“What does X stand for?”）一律 1，除非该术语本身就是运维 KPI 或告警概念（仍为 1，不因术语重要而升级）。
- 题目考的是“某机制存在的目的”：机制本身是运维日常调整的对象（如切换门限、DRX、负载均衡）→ 3；只是协议设计层面的目的 → 2。
- 拿不准在两级之间时取较低一级。

## 二、能力维度（单选）

| 维度 | 范围 |
| --- | --- |
| RAN | 无线接入：空口、物理层、RRC/MAC/RLC/PDCP、移动性、覆盖与干扰、侧行链路 |
| CORE | 核心网：5GC / EPC 网元、注册与会话管理、策略与计费、切片 |
| TRANSPORT | 传输与 IP：TCP/IP、以太网（802.3）、WLAN（802.11）、802.15.4 等 |
| OAM | 网管与运维：SON、MDT、性能 / 故障 / 配置管理、网络数据分析（NWDAF 的运维用途）、NFV MANO |
| SERVICE | 业务与 QoS：QoS 机制、IMS 与语音业务、MPS、V2X / UAS / 物联网等垂直业务 |
| SECURITY | 安全：认证、加密、密钥、隐私 |
| OTHER | 其他：RF 暴露安全、法规、通用概念 |

一题只选一个主维度，按“题目考的知识主要属于哪一层”判断。
